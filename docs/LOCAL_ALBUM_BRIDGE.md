# 本機歌詞與紀錄橋接製作流程

正式採用日期：2026-10-16（台灣時間）。適用於本專案，作為可選的製作輔助方式。它把本機已保存的歌詞交給瀏覽器，把瀏覽器實際觀察的結果存回本機；供應商操作仍使用原生可見 UI。權限以當批使用者授權為準，採用本文件不授權下一批生成、消耗額度、登入、上傳、發布或 Git 操作。

## 依據與穩定路徑

本次通過批次為 `places-to-go`、`words-to-say`，每張 20 首；40 次請求產生 80 個候選，按當批免試聽授權每曲任選一版，下載 40 個不同作品。完整證據見 [交付與驗收](../reports/album-production/20261016T091134Z/交付與驗收.md)、[最終摘要](../reports/album-production/20261016T091134Z/final-summary.json) 與 [額度收據](../reports/album-production/20261016T091134Z/quota-receipt.json)。

已通過的實作保存在該批次 [serve-inputs.cjs](../reports/album-production/20261016T091134Z/serve-inputs.cjs)、[evidence-server.cjs](../reports/album-production/20261016T091134Z/evidence-server.cjs)，作為不可覆寫的歷史證據。這兩支腳本含當批專輯、端口及 40 筆限制，不是可直接套用任何專輯的通用工具。重用時在新批次保存新設定／腳本與備份，先核對授權、輸出位置及限制；不得為重驗而重跑歷史製作工具。

穩定路徑仍是：本機完整歌詞與帳本 → 原生表單填寫及讀回 → 外部交易意圖 → 一次原生操作 → 平台結果讀回 → 原始檔驗證。橋接故障時可回到此路徑，先核對既有交易及作品，不重送狀態不明的請求。

## 1. 批次準備

- 讀取 `AGENTS.md`、製作帳本、既有結果與當批授權，保存 HEAD、暫存區、工作目錄差異、完整 SHA 清單及精確修改前備份。
- 固定批次 ID、專輯／曲目 ID、完整繁體歌詞、Styles、Title、模型、非敏感帳號別名、Voice 名稱及實際觀察 ID、用途、曲數與額度上限。未觀察的來源、授權、精確重置時刻保持 `unknown`／`null`。
- 原始歌詞先保存於本機。生成、解鎖、下載分開建立 durable intent；結果與失敗另存，不以後來成功覆蓋原先 FAIL。明確區分「請求數」、「候選數」、「不同作品解鎖數」及「下載嘗試數」。

## 2. 本機歌詞來源頁

只綁定 `127.0.0.1`，GET 僅輸出當批精確白名單的歌詞／提示詞 JSON，以 HTML 跳脫後的可見文字呈現。未知路徑回覆 404；不提供任意磁碟讀取、不列目錄、不開放跨網段。端口按本輪可用情況設定並記錄，不視歷史端口為固定資源。

瀏覽器透過正式工具導向該本機頁，讀取可見文字並解析，依曲目 ID 對應原生 Lyrics、Styles、Title。這是使用者已保存內容的轉抄輔助，不得讀取供應商隱藏狀態、私有 API、憑證、Cookie 或其他工作階段資料。

送出前必須讀回每個原生欄位並比對本機來源，完整保留中文內容與段落。若工具把段落分隔表示為不同換行，只能使用明確記錄的換行正規化；不得以模糊比對掩蓋缺字、改詞、截斷或換曲。

Voice 先精確搜尋、選取並核對實際身分 ID，再提交；名稱、列表位置或初次點擊本身不足以確認。生成後逐候選核對作品 ID、實際作品頁、標題、模型與可見 Voice 證據。本人 Voice 設定通過與實際演唱聲音聽審分開記錄。

## 3. 本機證據接收表單

接收端只綁定 `127.0.0.1`，透過可見的本機表單接收實際觀察資料；POST 必須核對包含端口的精確 Origin。限制 request bytes、解析 JSON，核對當批欄位與筆數上限，不接受任意目標路徑。已通過批次限制為 12 MiB、各 40 筆生成／下載記錄；其他批次須重新按授權設定，不能直接擴大額度。

每次保存以時間戳新檔名及 `wx` 獨佔建立，發生衝突則拒絕覆寫；截圖如有保存也使用獨佔檔名，JSON 記錄實際相對路徑。表單回覆僅代表本機接收，必須讀回檔案、解析內容及實際 bytes，與帳本／交易結果對帳；不代表 Suno 生成或下載已完成。

每個候選最少保存：供應商、實際作品 ID／頁面、標題、生成時間、模型、非敏感帳號別名、歌詞／提示詞或其證據、Voice 設定證據、用途、生成／選用／下載狀態。下載成功後補原檔 path、bytes、完整 SHA-256；未下載者仍保留備註，未知值不猜造。每次保存的快照與失敗讀值都留下，追加技術驗證可用新事件，不改寫原始觀察。

## 4. 額度、下載與恢復

1. 開始前核對帳號、成本、生成餘額及下載額度，結束後重新載入權威帳號頁讀回。創作頁快取徽章與帳號頁分欄保存；不由延遲徽章推算消耗。只有日期而無時刻／時區的重置資訊保持未知。
2. 曲目用 `selectedResult` 連到精確候選，下載意圖包含該作品 ID、選用理由及剩餘上限。任選一版、不試聽是本次特定授權，後續批次需重新確定接受方式。
3. 開啟同作品的原生下載選單，確認 MP3 格式與實際按鈕狀態；不要假設預設未勾選。先掛下載事件，再對唯一原生控制項操作一次。
4. 事件逾時先讀回 UI、原下載目錄的新檔、bytes、寫入狀態及 `.crdownload`。檔案已到達時直接驗證，不以沒有事件為理由再下載。狀態未知時保留 intent 並停止相依操作。
5. 若明確顯示下載失敗，且已證明無檔案／暫存檔／進行中下載，重新讀回同作品「已解鎖」及原生 Download 按鈕；在授權範圍內寫一次恢復意圖，才做一次同作品原生下載。不得再次解鎖、改作品、重新生成或藉此擴大配額；再次失敗／未知即停止。工具安全拒絕不得改用其他後端繞過。
6. 原始下載保留原樣，再建立專案保存副本與正式音檔，三者 bytes／SHA 必須相同。檔案非零、寫入完成並無該交易的暫存下載後，依專輯驗證規則執行 FFprobe／FFmpeg 完整解碼至宣告結尾，報告標示 `fullDecodePerformedThisRun`。

本批次第二張第 6 首的單次已解鎖下載恢復，見 [恢復意圖](../albums/words-to-say/transactions/06-download-recovery-intent.json)；40 次不同作品解鎖、41 次原生下載嘗試分開記錄。此案例不是所有下載失敗都可重試的授權。

## 5. 交付與收尾驗收

- 對帳候選、曲目、選用結果、交易、來源 URL、三份音檔 bytes／SHA、實際總長及扣額；所有矛盾或缺值保留待確認。
- `audio_presence` 與 `vocals` 分欄。未聽審時 `vocals=unknown`；有聲、ASR 無詞、Voice 設定均不能替代實際人聲／聲音身分／藝術接受。技術交付維持 `local_complete_unreviewed_unpublished` 等明確狀態。
- 使用中文路徑時沿用通過的 PowerShell 7 打包路徑；先檢查版本，使用新 ZIP 路徑且拒絕覆寫。逐項核對預期名稱、項數、bytes 與內容 SHA，不只看 ZIP 存在或大小。原先 PowerShell 5.1 失敗 ZIP、腳本及錯誤保留。
- 專輯驗證維持唯讀預設、新報告獨佔建立。以當輪前後基線證明未授權檔案未變、修改前備份正確；不可用本輪雜湊檢查冒充重新解碼。
- 本機預覽、公開 HTTP、瀏覽器播放、手機實機、人工聽審、發布核准分開驗收。共用庫只先追加本機待整理清單；未完成雲端正式索引／READY 去重前不得宣稱入庫完成。
- 收尾記錄並停止本輪自建的歌詞與證據服務，讀回端口關閉；不關閉其他任務的服務。另保留的本機預覽須明列用途與端口。

## 正式採用與歷史紀錄

本次試行的優點是降低大量轉抄錯誤，並保留每次平台讀回及本機接收結果；取捨是需要管理兩個短期本機服務，且批次腳本仍須核對設定。使用者已於 2026-10-16 明確批准納入本專案，未升級為全局規則。舊交付報告的「尚未升級」保持原文，以根目錄 [AGENTS.md](../AGENTS.md) 及本文件記錄後續採用。

本次只正式化已通過流程，沒有啟動橋接服務、操作供應商、重下載、重新打包或執行 Git 暫存／提交／推送／部署。
